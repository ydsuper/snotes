设计模式

概念与作用​

恒古至今，软件开发过程中验证总结下来的经验，得出的一套通用代码设计方案。在类似的场景下，就可以快速参考设计模式实现代码，不仅提高了编码效率，也提升了代码的可扩展性、可重用性与可维护性。

作用： 概念本身就是最佳实践，最佳实践意味着各方面都是较优的方案，同时这还是通用的方案，也极大简化了内部的沟通成本，大家都熟悉设计模式，那么大家也能更快的理解设计的含义，理解开发者的设计意图与代码含义。

设计模式分类​

23 种设计模式可以分为三大类：创建型、结构性、行为型

  • 创建型模式（Creational Patterns）

    用于创建对象的模式，同时隐藏对象创建的逻辑，避免代码中出现大量 new 操作和复杂的创建逻辑。

    常用模式：单例模式、工厂模式、建造者模式；

    不常见：原型模式。

  • 结构型模式（Structural Patterns）

    用于处理对象组合的结构，关注类与对象的组合。

    常用模式：适配器模式、桥接模式、组合模式、装饰器模式；

    不常见的：外观模式（门面模式）、享元模式。

  • 行为型模式（Behavioral Patterns）

    用于定义对象如何相互协作以完成单个对象无法单独实现的任务。

    常用模式：观察者模式、责任链模式、策略模式、模板模式、状态模式、迭代器模式；

    不常见的：备忘录模式、命令模式、中介者模式、访问者模式、解释器模式。

单例模式​

一个类只有一个实例，这个类就是单例类，这种设计就是单例模式。主要用于资源管理（避免资源冲突），保证全局唯一的场景。

使用场景：

  • 配置管理

    全局配置，此配置理论上需要保证唯一性，确保读取到的配置是同一份，是一致的，非常适合单例实现。

  • 连接池、线程池

    池化资源需要保证唯一性，控制具体池化资源的数量，便于管理和监控。

还有日志、缓存等需要全局唯一避免资源冲突的场景。

具体实现方式：

  • 懒汉式单例

    public class Singleton {
        private static Singleton instance;
        // 私有构造函数，防止外部实例化
        private Singleton() {}
        // 加锁，保护线程安全（多线程并发访问可能产生多个实例）
        public static synchronized Singleton getInstance() {
            if (instance == null) {
                instance = new Singleton();
            }
            return instance;
        }
    }

    //【双重检查锁定版本】
    public class Singleton {
        private static volatile Singleton instance;
        // 私有构造函数，防止外部实例化
        private Singleton() {}
        public static Singleton getInstance() {
            if (instance == null) {
                synchronized (Singleton.class) {
                    if (instance == null) {
                        instance = new Singleton();
                    }
                }
            }
            return instance;
        }
    }

  • 饿汉式单例

    public class Singleton {
        private static final Singleton instance = new Singleton();
        // 私有构造函数，防止外部实例化
        private Singleton() {}
        public static Singleton getInstance() {
            return instance;
        }
    }

    // 静态内部类，既安全也延迟加载（上面的没有延迟加载）
    public class Singleton {
        private Singleton() {}
        private static class SingletonHolder {
            private static final Singleton INSTANCE = new Singleton();
        }
        public static Singleton getInstance() {
            return SingletonHolder.INSTANCE;
        }
    }
