FreeRTOS​

1. 裸机多任务和RTOS的区别？​

裸机多任务

  • 静态创建（动态则需要将数据结构设置为链表形式，再来add和remove）

RTOS

  • 动态创建

总结：有一个装任务的容器

2. RTOS底层原理​

  1. 多任务启动流程：创建Idle Task(最低优先级)、创建Timer Task、启动调度器、错误任务处理
  2. 启动调度器：配置中断优先级、初始化系统时钟.....启动第一个任务.....
  3. 启动第一个任务：重置MSP（主栈指针）、清除FPU使用标志、全局启用中断、执行SVC调用
  4. MSP、PSP、保护现场恢复现场、TCB ....

细节：

  1. taskENTER_CRITICAL();
    // ... 批处理
    taskEXIT_CRITICAL();

    // 以上是配对出现，出现时，则...中的代码会一并提交到调度器处理，并排序（内部有套排序逻辑）执行。否则，按顺序执行，不看优先级

  2. __WAAK：实现一个"弱"的函数，如果有新的实现，则忽视它，如果没有实现，则使用它

  3. pdMS_TO_TICKS：一个滴答时间（1ms） pdMS_TO_TICKS(portMAX_DELAY) 是无限时间

3. RTOS功能描述​

  1. 创建任务、删除任务、RTOS延时、任务优先级、任务挂起和恢复、xxxFromISR、分级配置、软件Timer、信号量【二进制、计数型、互斥锁、递归互斥锁】、消息队列、事件组、通知
  2. 分级配置：configMAX_SYSCALL_INTERRUPT_PRIORITY
  3. 信号量
    • 二进制信号量：Give发送，Take接收，理解为只有一个灯，所有任务优先级高先抢灯（去灭）
    • 计数型信号量：在二进制基础上，可以添加N个灯，设置开灯的初始数。
    • 互斥锁（互斥信号量）：Task上锁，Give解锁。不可上多次锁
    • 递归互斥锁：可以上多次锁，但也需要多次解锁
  4. 消息队列
    • 可以发送具体数据，架构和信号量差不多
    • 发送消息：xQueueSend(句柄，指针数据，栈满任务加入需等待时间) 接收消息：xQueueReceive(句柄，拷贝指针，栈空时需等待时间)
  5. 事件组
    • uint32_t，32bit，事件：发生(1) / 没发生(0)，理论32个事件：实际8(内部保留) + 24个事件
    • 创建事件组：xEventGroupCreate()，返回事件句柄 产生事件：xEventGroupSetBits(句柄，事件8+24位 (例:0x01) ） 接收事件：xEventGroupWaitBits(句柄，等哪个bit位，等到后是否将事件置为0(pdTRUE/pdFALSE)，要不要等所有事件都产生了再触发(pdTRUE/pdFALSE)，阻塞等待多久)
    • 多任务等待相同的事件时，都能触发！并非优先级高的触发
    • 同步事件：xEventGroupSync(句柄，设置事件，等待事件，阻塞等待多久)
  6. 通知
    • 发送通知：xTaskNotify(句柄，通知数据，如何更新任务的通知值) 【更新方式需注意】 接收通知：ulTaskNotifyWait(进入时清除位，退出时要清空位，保存通知值，接收等待时间)
    • 了解为主，此封装较重，用的较少

RAM​

1. 软实现和硬实现的不同，选型​

  • 软实现需要调用SCL和SDL2个GPIO，硬实现是工厂直接初始化出来的
  • 硬比软效率更高

2. 不同协议如何选型​

  • 硬件定好画好，价格有关

3. I2C​

  • 低位先行还是高位先行
  • 温湿度传感器：AHT20(I2C)、DHT11(单种线)

4. SPI​

  • 全双工，四根线

5. I2C 和 SPI​

  • SPI 比 I2C 速度快，具体快多少？
  • SPI全双工，I2C半双工

6. 开发全流程​

  • 新项目：接到一个demo，或者完整的，跑通串口，根据满足标准：比如检测ADC、马达转速，硬件耗电
  • 维护开发项目：打开当前遇到的问题，相关的串口调试，了解功能用到的引脚，定位具体细节问题功能。
