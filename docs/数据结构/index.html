数据结构

绪论​

简介概述​

程序设计的实质就是对确定的问题选择一种好的结构加上设计一种好的算法。 即: 数据结构 + 算法 = 程序

编写一个"好"的程序：

  • 分析待处理的数据之间存在的 关系，进行合理组织并存入计算机中

  • 在此基础上，设计算法处理数据

  • 数据结构是算法实现的 基础，算法总是要依赖于某种 数据结构 来实现

    数据结构与算法如影相随 不可分离

三种基本结构​

  • 线性数据结构​

    计算机处理的对象之间存在着一个跟一个的线性关系，这类模型称之为线性数据结构。

  • 树形数据结构​

    数据之间有明显的层次关系，一个后面可以跟多个，这是一个典型的树形结构，树形结构是一类非数值计算问题的数学模型，也是一种数据结构。

  • 图形数据结构​

    数据之间存在多对多的关系。

数据​

数据是计算机操作的对象。文字、表格、视频等等都被称为数据，音乐是音频数据、图片是图像数据，这里所说的数据就是一个符号。

符号具备两个前提：

  • 一是可以输入到计算机中
  • 二是能被计算机程序处理
  • 数值型数据，可以进行 数值 计算
  • 文字类字符，如 word 软件， 就需要进行 非数值 的处理
  • 声音、图像、视频等，通过编码的手段将他们变成 字符数据 来处理

数据元素和数据项​

  • 数据元素就是组成数据的、有一定意义的 基本单位，在计算机中通常作为一个整体处理，也被叫做 记录

  • 一个 数据元素 可由若干个 数据项 组成，也把数据项称为数据元素的域、字段、关键字

    如： 图书管理系统，操作对象就是"书"，数据元素就是一本一本的书 ，每本书由书名、作者、出版社等等来描述，这些就是一个一个的数据项。

  • 通常，把具有相同性质的数据元素的集合称为 数据对象，它是数据的一个子集

    对于一类问题，处理的数据是具有相同性质的，也就是说属于同一个数据对象。 如：图书管理系统 中数据对象是书、文件目录系统中数据对象是文件夹、地图中的数据是地点。

  • 数据元素是数据对象的一个 实例

数据结构​

数据元素之间不是独立的，而是存在特点关系的，将这种关系称为结构。 数据结构就是互相之间存在着一种或多种关系的数据元素的集合。有两个要素：数据元素集合、关系的集合。

  • 形式上，采用 二元组 进行表示：DS（Data Structure）= (D, R)​

    D 是数据元素的有限集，R 是 D 中数据元素之间关系的有限集

  • 数据结构，分为 逻辑结构 和 物理结构​

逻辑结构​

逻辑结构指在抽象的层面上数据对象中数据元素之间的关系。

  • 集合结构：数据元素间的关系是"属于同一个集合"​

    集合中数据元素之间没有特定的关系，通常具体处理时会人为加上某种关系，可以是线性树形图形的。

  • 线性结构：数据元素之间存在着一对一的关系​
  • 树形结构：数据元素之间存在着一对多的关系​
  • 图形结构：数据元素之间存在着多对多的关系​

物理结构​

物理结构是指数据的逻辑结构在计算机中的存储形式，是逻辑结构在计算机中的实现，包括数据元素的存储及元素之间关系的存储。

  • 顺序存储结构：把数据元素存放在地址 连续的 存储单元中，数据元素之间的 逻辑关系和物理位置一致​

    顺序存储结构是一种最基本的存储表示方法，通常借助程序设计语言中的 数组 来实现。

  • 链式存储结构：把数据元素存放在 任意的 存储单元中，这组存储单元 可以连续也可以不连续​

    数据元素之间的物理位置 不能反映 其逻辑关系，借助 指针字段 来存放 下一个 数据元素所在的 位置，这需要给每个数据元素 附设 一个指针，用 指针 来反映数据元素之间的 逻辑关系。

    链式存储结构通常借助于程序设计语言中的 指针类型 来实现。

    • 头指针：指向第一个数据元素的指针，通常称为头指针，可以通过其找到所有数据元素的位置​
  • 索引存储结构​
  • 散列存储结构​

结构小结​

  • 逻辑结构是 面向问题 的，在 抽象的层面 上分析问题

  • 物理结构是 面向计算机 的，它的基本目标是将 数据及其关系 存储到计算机的内存中

  • 集合结构、线性结构、树形结构、图形结构。 可以利用顺序存储结构、链式存储结构或者这两种的组合实现在计算机中的存储

    将数据结构存入计算机后，就可以设计程序，让计算机完成我们所需要的运算。 对于一个数据结构，具体的操作依据实际问题的不同有所不同。

  • 常用的操作：有插入、删除、修改、查找、排序

数据结构分两次层次讨论

  • 面向问题的 逻辑层面
    • 抽象出来计算机要处理的对象——非数值的数据
    • 寻求数据元素之间的逻辑关系
    • 针对问题抽象出操作集合
  • 面向计算机的 物理层面
    • 将数据及数据之间的关系存入计算机
    • 设计算法实现各种操作
数据结构是一门研究 非数值计算 的程序设计问题中的操作对象、对象之间的关系以及在此之上的一系列操作的学科。​

算法基本概念​

算法简单来说就是解决问题的方法，是对问题求解过程的描述。

一问多答​

// 母鸡5文/只、公鸡3文/只、小鸡1文/3只，用100文钱买100只鸡，问这100只鸡里有多少只公鸡?多少只母鸡?
/* 设公鸡x，母鸡y，小鸡z */
//【方法一】（三层循环）
for (let x = 1; x < 100; x++) {
  for (let y = 1; y < 100; y++) {
    for (let z = 1; z < 100; z++) {
      if (x + y + z === 100 && x * 5 + y * 3 + z / 3 === 100) {
        console.log(`公鸡${x}只，母鸡${y}，小鸡${z}只`);
      }
    }
  }
}

//【方法二】（双层循环）
for (let x = 1; x < 20; x++) {
  for (let y = 1; y < 33; y++) {
    let z = 100 - x - y;
    if (z % 3 === 0 && x * 5 + y * 3 + z / 3 === 100) {
      console.log(`公鸡${x}只，母鸡${y}，小鸡${z}只`);
    }
  }
}

//【方法三】（单层循环）[非最优]
for (let x = 1; x < 20; x++) {
  let y = 25 - (7 / 4) * x;
  let z = 100 - x - y;
  if (z % 3 === 0 && x * 5 + y * 3 + z / 3 === 100) {
    console.log(`公鸡${x}只，母鸡${y}，小鸡${z}只`);
  }
}

算法五特性​

  • 0 个或多个输入​

    绝大多数算法，输入参数是必要的，但也有个别情况，如：仅仅要求输出一段文字，就可以没有输入了。

  • 至少有一个输出​

    输出就是把结果呈现出来（问题解决了，结果不呈现？有意义吗？）

  • 有穷性​

    一个算法在执行有限步之后能够结束，不会出现死循环。

  • 确定性​

    算法的每一步必须有确切的定义，不会出现 二义性。

  • 可行性​

    算法中的每一步都是可行的，每一步都能够通过执行有限次数完成。就是算法可以转换成程序，在机器上运行，并得到正确结果。

算法四要求​

  • 算法要正确​

    算法的执行结果应当满足预先规定的功能和性能要求。

  • 可读性​

    算法首先应该便于人们理解和相互交流，其次才是机器可执行。所以一个算法应当思路清晰，层次分明，简单明了，易读易懂。

  • 健壮性​

    作为一个好的算法，当输入不合法数据时，应能适当地做出正确反应或进行相应的处理，而不至于产生一些莫名其妙的输出结果。

  • 高效率低存储​

    算法效率通常指算法的执行时间。对于同一个问题如果有多个算法可以解决，执行时间短的算法其效率高。所谓存储量的要求，是指算法在执行过程中所产生的最大存储空间。这两者都与问题规模有关。

算法的描述​

  • 使用自然语言​

    为了便于理解和阅读，最好采取分步骤的叙述方式，将处理步骤描述得更具条理性和准确性。

  • 使用流程图​

    用流程图描述算法时，要注意使用规范的流图符号。

  • 使用某种程序设计语言​

    直接使用程序设计语言并不容易，而且不太直观，常常需要借助于注释才能使人看明白。

  • 使用类程序设计语言​

    类语言是以某种通用的程序设计语言作为基础，对其略加改造而形成的一种"非正规的"语言。 如：类 C、类 PASCAL、类 JAVA 等都是常用的算法描述工具。用类语言书写的程序称为伪程序或伪代码。

算法效率的评价方法​

评价算法的好坏，简单说：就是少花时间，少用空间。

在 计算机程序编制前，依据统计方法对算法进行估算 一个高级程序设计语言编写的程序在计算机上运行时，所消耗的时间取决于 4 个因素：

  • 算法采用的策略、方法​

    算法好坏的根本

  • 编译产生的代码质量​

    要系统软件来支持

  • 问题的输入规模​

    特定算法的运行工作量的大小

  • 机器执行指令的速度​

    要看硬件的性能

输入量大小问题​

所谓问题的规模，就是指输入量的大小。

例: 在1+2+3+..+100问题中，问题规模就是100

一个算法是由一条条指令构成的，算法的指令通常称为语句 ∴ 算法的执行时间和算法中所有语句执行次数的总和成正比

▌ 问题：1+2+3+..+100【求和】
// 一、利用for循环：1.声明变量 2.for循环 3.累加求和 4.打印
   ● 算法中语句执行次数为：1 + (n+1) + n + 1 => 2n+3

// 二、利用高斯算法：1.声明变量 2.直接计算和 3.打印
   ● 算法中语句执行次数为：1 + 1 + 1 => 3

▲ 这两个算法核心操作分别是：sum=sum+i; sum=(n+1)*n/2; 执行次数分别是n次和1次，算法好坏显而易见
∴ 算法的运行时间与核心操作的执行次数成正比（这里的核心操作称之为：原操作）

不计哪些循环索引的递增和循环条件、变量声明、输入输出等等，只关心原操作的执行次数。以原操作重复执行的次数作为算法的时间度量。 一般情况下，算法中原操作重复执行的次数是问题规模 n 的某个函数 f(n)。 进而还要分析 f(n)随 n 的增大，它的增大趋势，也就是 f(n)的数量级，作为评价算法性能的依据。

时间复杂度​

所谓算法的时间复杂度，就是算法的时间量度。记作：T(n) = O(f(n))

O(f(n)) 读作 "大 O"，是时间复杂度的记号。用 "大 O" 分析算法实际上就是：抓大放小，要事为先。

O(f(n))：表示随问题规模 n 的增大，算法的执行时间的增长率和 f(n)的增长率相同，称作算法的渐进时间复杂度，简称时间复杂度。

如果一个算法，随着问题规模 n 的增大，原操作的执行次数的增长率如果比较缓慢，这算法的效率就比较好。

大 O 阶的推导​
  • 顺序结构的时间复杂度​

    顺序结构、分支结构的程序，不管代码有多少行，执行次数不会随着 n 的变化而发生变化。 它与问题规模 n 的大小无关，执行次数是恒定的，用 O(1) 来表示其时间复杂度，通常称之为 常量阶。

  • 单循环结构的时间复杂度​

    例原操作为: sum=sum+i，执行次数为 n，其时间复杂度为 O(n)，我们称之为 线性阶。

  • 多重循环结构的时间复杂度​

    如果双重循环：例原操作为: x=x+1，执行次数为 n²，其时间复杂度为 O(n²)，我们称之为 平方阶。

    如果三重循环：其时间复杂度为 O(n³)，我们称之为 立方阶，以此类推。

  • 倍数结构的时间复杂度​

    由 2ⁿ = y 得 n = log₂y，循环的执行次数为 log₂y，时间复杂度为 O(log₂y)，我们称之为 对数阶。

▌ 常用的时间复杂度
 常量阶O(1)、线性阶O(n)、平方阶O(n²)、对数阶O(lbn)

▌ 其他算法呈现的时间复杂度
 二维阶O(n lbn)、立方阶O(n³)、指数阶(2ⁿ)、阶乘阶O(n!)等

最优、最差与平均时间复杂度​

算法的效率不仅依赖于问题的规模，还与问题的初始输入数据集有关。如果一个算法对于相同规模的不同输入，原操作的执行次数不同，则分析算法的最优、最差、平均性能。

  • 最优时间复杂度​

    指输入规模为 n 时，花费时间最少的时间复杂度。

  • 最差时间复杂度​

    指输入规模为 n 时，花费时间最多的时间复杂度。

  • 平均时间复杂度​

    指在 "典型" 与 "随机" 输入的情况下，算法具有的时间复杂度。

    平均时间复杂度是从 概率 的角度进行分析的，研究它的直接方法就是将规模为 n 的实例划分为几种类型

    很多情况下算法的时间复杂度很难计算，因此，可以采用算法在最坏情况下的时间复杂度作为度量依据。​

空间复杂度​

类似于算法的时间复杂度，采用空间复杂度作为算法所需存储空间的度量。记住：S(n) = O(f(n))（n为问题规模，定义为该算法所耗费空间的数量级）

一个算法在运行过程中所占的存储空间，包含三个方面：

  • 算法 本身所占用的存储空间​

    与算法书写长短成正比，要压缩这方面的存储空间，就必须编写出较短的算法。

  • 算法的 输入输出数据 所占用的存储空间​

    由要解决的问题决定的，它不随着算法的不同而改变。

  • 算法的 运行过程中临时 占用的存储空间​

    随算法的不同而异。

    • 有的算法只需要占用少量的临时工作单元，而且不随问题规模的大小而改变，我们称这种算法是 "原地工作"，是节省存储的算法。
    • 有的算法需要占用的临时工作单元数与解决问题的规模 n 有关，它随着 n 的增大而增大，例如快速排序和归并排序算法就属于这种情况。
算法的执行时间的耗费和所占存储空间的耗费两者是矛盾的，难以兼得，通常算法执行时间上的节省一定是以增加空间存储为代价的。​

线性表​

线性表指将数据排成像一条线一样的结构（数组、链表、栈、队列），注意此处并没有说是数据连续，线是直线等字眼。 非线性数据结构：树、图等。

线性表的特点​

  • 它由 n 个同类型的元素组成
  • 除第一个元素和最后一个元素，其他每个数据元素有且仅有一个前驱和一个后继
  • 其长度可以动态的增长或减少
  • 可以对线性表中任何数据元素进行访问
  • 数据元素的插入和删除操作可以在线性表中的任何位置
  • 可以求线性表中指定元素的前驱和后继

线性表存储结构​

  • 顺序存储结构：数组​

    顺序存储结构表示的线性表称为: 顺序表。

  • 链式存储结构：链表​

    链式存储结构表示的线性表称为: 链表，链表有分单链表、双向链表、循环链表。

时间复杂度​

概念​

全称：渐进时间复杂度，作用：考量代码执行效率的一个非常重要的指标。 时间复杂度是抛开算法运行的软硬件环境，只考虑算法与问题规模之间的关系。

算法的时间复杂度反映了：程序执行时间随输入规模增长而增长的量级，在很大程度上能很好 反映出算法的优劣与否。 算法执行时间：需通过依据该算法编制的程序在计算机上运行时所消耗的时间来度量。

时间复杂度表述​

一般使用O表示时间复杂度(忽略常量)：O(1)、O(n)、O(n^2)、O(nlogN)、O(n^3)等（算法和n呈线性关系）

// 例T = 2n + 2  --> 时间复杂度是 O(n)T = 999n + 1000  --> 时间复杂度是 O(n)T = n*n + 999  --> 时间复杂度是 O(n^2)// 问：O(n^2)的时间复杂度一定大于O(n)吗?答：不一定，主要看n的大小。

常数阶 O(1)、对数阶 O(logN)、线性阶 O(n)、线性对数阶 O(nlogN)、平方阶 O(n²)、立方阶 O(n³)、K 次方阶 O(n^k)、指数阶(2^n)（依次的时间复杂度越来越大，执行的效率越来越低）

时间复杂度分析​

// 时间复杂度：O(1) ▶ 固定的代码执行次数     // 时间复杂度：O(n) ▶ 例:单个for循环n次     // 时间复杂度：O(n^2) ▶ 例:for循环嵌套

  • 最好时间复杂度

    在最理想的情况下，执行这段代码的时间。如: 第一次执行即得所要结果

  • 最坏时间复杂度

    在最糟糕的情况下，执行这段代码的时间复杂度，如: 要一个个查验整个数组的长度 O(n)

    通常使用最坏时间复杂度表示一个算法的复杂度。

  • 平均时间复杂度

    其实最好与最坏情况是极端情况，发生的概率并不大。所以为了更准确的表示平均情况下的时间复杂度，引入另一个改变：平均情况时间复杂度。

    公式：平均时间复杂度 = 累加每种遍历的元素个数 / 所有情况的数量

    • 期望时间复杂度 考虑概率的平均情况复杂度，是概率论中的加权平均值，也叫作期望值，所有平均时间复杂度全称为：加权平均时间复杂度或者期望时间复杂度。

  • 均摊时间复杂度

    均摊时间复杂度是一种特殊的平均时间复杂度，分析方式: 摊还分析 or 平摊分析 应用场景：对于有一定规律的复杂度，如多个 O(1)后接一个 O(n)（均摊后为 O(1)），将耗时多的复杂度均摊到耗时少的复杂度上，所得到的复杂度即为均摊时间复杂度

注意：多数情况下，我们不需要区分最好、最坏、平均情况时间复杂度。只有同一块代码在不同情况下时间复杂度有量级差距，我们才会区分 3 种情况，为的是更有效的描述代码的时间复杂度。

模式匹配算法​

  • BF（Brute Force）算法

    BF 算法是一种暴力(蛮力)算法, 其思想就是将目标串S的第一字符和模式串T的第一字符进行匹配, 若相等, 则继续比较S的第二字符和T的第二字符; 若不相等, 则比较S的第二字符和T的第一字符, 依次比较下去, 直到得出最后的匹配结果。BM 算法时间复杂度为 O(m*n)

  • KMP（D.E.Knuth、J.H.Morris 和 V.R.Pratt）算法

    KMP 算法的核心是利用匹配失败后的信息, 尽量减少模式串与主串的匹配次数以达到快速匹配的目的。具体实现就是通过一个 next() 函数实现, 函数本身包含了模式串的局部匹配信息。KMP 算法的时间复杂度 O(m+n)

    • 时间复杂度 O(m)：next 数组
    • 时间复杂度 O(n)：主串长度
    class Kmp {
      // ss: 原串(string)  pp: 匹配串(pattern)
      public int strStr(String ss, String pp) {
        if (pp.isEmpty()) return 0;

        // 分别读取原串和匹配串的长度
        int n = ss.length();
        int m = pp.length();
        // 原串和匹配串前面都加空格，使其下标从 1 开始
        ss = " " + ss;
        pp = " " + pp;

        // 字符串转字符数组
        char[] s = ss.toCharArray();
        char[] p = pp.toCharArray();

        // 构建 next 数组，数组长度为匹配串的长度（next 数组是和匹配串相关的）
        int[] next = new int[m + 1]; // m+1 因为串前面加了空格
        // 构造过程 i = 2，j = 0 开始，i 小于等于匹配串长度 【构造 i 从 2 开始】
        for (int i = 2, j = 0; i <= m; i++) {
          // 匹配不成功的话，j = next(j)
          while (j > 0 && p[i] != p[j + 1]) j = next[j];
          // 匹配成功的话，先让 j++
          if (p[i] == p[j + 1]) j++;
          // 更新 next[i]，结束本次循环，i++
          next[i] = j;
        }
        System.out.println(Arrays.toString(next));

        // 匹配过程，i = 1，j = 0    开始，i 小于等于原串长度 【匹配 i 从 1 开始】
        for (int i = 1, j = 0; i <= n; i++) { // i从1开始 因为起始有个空格
          // 匹配不成功 j = next(j)
          while (j > 0 && s[i] != p[j + 1]) j = next[j];
          // 匹配成功的话，先让 j++，结束本次循环后 i++
          if (s[i] == p[j + 1]) j++;
          // 整一段匹配成功，直接返回下标
          if (j == m) return i - m;
        }

        return -1;
      }
    }

KMP-next【草稿】

  • ababababsa 梳理所有子串的最长相等前后缀
  • 通过下标 i 和 j （i 是后缀后一位 j 是前缀后一位 )

树​

树是由n（n≥0）个结点所构成的有限集合，当n=0时，称为空树; 当n>0时，n个结点满足以下条件：

  • 有且仅有一个称为根的结点
  • 其余结点可分为 m (m≥0) 个互不相交的有限集合，且每一个集合又构成一棵树，这棵树称为是根结点的子树

树的特点​

  • 每个结点都只有有限个子结点或无子结点
  • 没有父结点的结点称为根结点
  • 每一个非根结点有且只有一个父结点
  • 除了根结点外，每个子结点可以分为多个不相交的子树
  • 树里面没有环路 cycle

二叉树​

二叉树，顾名思义，每个结点最多有两个“叉”，也就是两个子结点（树的度最大为2），分别是左子结点和右子结点。二叉树也可以是空树。

二叉树的五种基本形态：

  • 空树
  • 只含根结点
  • 右子树为空树
  • 左子树为空树
  • 左右子树均不为空树

满二叉树​

叶子结点全都在最底层，除了叶子结点之外，每个结点都有左右两个子结点，这种二叉树就叫作满二叉树。

完全二叉树​

叶子结点都在最底下两层，最后一层的叶子结点都靠左排列不能间断，并且除了最后一层，其他层的结点数都要达到最大(2)，这种二叉树称作完全二叉树。

单分支树的定义​

  • 左支树：所有结点都没有右孩子的二叉树​
  • 右支树：所有结点都没有左孩子的二叉树​

二叉树的性质​

前三个性质是对于任意二叉树；后两个性质对于完全二叉树

  • 性质一：在二叉树的第 i 层上至多有 2^i^ 个结点。(i≥0)
  • 性质二：深度为 h （h≥1）的二叉树上至多含 2^h^-1 个结点
  • 性质三：对于任何一棵二叉树，若其叶结点的个数为 n0 ，度为 2 的结点个数为 n2，则有n0 = n2+1
  • 性质四：具有 n 个结点的完全二叉树的深度为 ⌊ log2n ⌋ + 1 或 ⌈ log2(n+1) ⌉
  • 性质五：若对含 n 个结点的完全二叉树从上到下且从左至右进行 0 至 n-1 的编号，则对完全二叉树中任意一个编号为 i 的结点,有：
    • (1) 若 i=0，则该结点是二叉树的根，无双亲，否则编号为 ⌊ (i - 1) / 2 ⌋ 的结点为其双亲结点；
    • (2) 若 2i+1≥n，则该结点无左孩子，否则，编号为 2i+1 的结点为其左孩子结点；
    • (3) 若 2i+2≥n，则该结点无右孩子结点，否则，编号为 2i+2 的结点为其右孩子结点

哈夫曼树​

哈夫曼树中只有叶结点和双分支结点。

基本概念​
  • 结点间的路径：从一个结点到另一个结点所经历的结点和分支序列​
  • 结点的路径长度：从根结点到该结点的路径上分支的数目​
  • 结点的权：在实际应用中，给树中的每个结点赋予一个具有某种实际意义的数值，该值被称为该结点的权值​
  • 结点的带权路径长度：结点的权值 与 结点的路径长度 的乘积​
  • 树的带权路径长度：树中所有叶结点的带权路径长度之和​

    假设树上有 n 个叶结点，通常记作：$WPL=\sum\_{i=1}^{n}{W_i}\*{L_i} $ 1 其中 Li 为带权 Wi 的叶子结点的带权路径长度

最优二叉树​

给定n个权值并作为n个叶结点按一定规则构造一颗二叉树，使其带权路径长度达到最小值，则这棵二叉树被称为最优二叉树。也称哈夫曼树。 在所有含有n个叶子结点、并带相同权值的二叉树中，必存在一颗其带权路径长度取最小值的树，这树就是“最优树”。

哈夫曼树的算法​
  • (1) 根据给定的 n 个权值 {w1, w2, …, wn}，构造 一个由 n 棵二叉树所构成的森林 F = {T1, T2, … , Tn}，其中每一棵二叉树只有一个根结点，并且根结点的权值分别为 w1, w2, …, wn
  • (2) 在二叉树森林 F 中选取根结点的权值最小和次小的两棵二叉树，分别把它们作为左子树和右子树去构造一棵新二叉树，新二叉树的根结点权值为其左、右子树根结点的权值之和
  • (3) 作为新二叉树的左、右子树的这两棵二叉树从森林 F 中删除，同时加入刚生成的新二叉树
  • (4) 重复 (2) 和 (3) 两步，直至 F 中只含一棵二叉树为止，则这种棵二叉树就是所构成的哈夫曼树

图​

图的概述​

图中的每一个元素称之为顶点（Vertex），并且图中的一个顶点可以与其他任意顶点建立连接关系，将这种建立的关系叫做边（Edge）。 有顶点集合边集组成，记为G=(V, E)

  • 由顶点集和边集组成​
  • 记为 G = (V, E)，其中 V 是有穷非空集合，称为顶点集，v∈V 称为顶点。E 是有穷集合，称为边集，e∈E称为边​
  • 无向边：e = (u, v) = (v, u), 其中 u, v ∈ V, 边(u, v) 与边 (v, u) 是相同的​
  • 无向图：全部由无向边构成的图​
  • 有向边：e = <u, v> = <v, u>, 其中 u, v ∈ V, 简称为弧, 其中 u 为始点 或 弧尾, v 为终点或弧头, 边<u, v> 与边<v, u> 是不同的​
  • 有向图：全部由有向边构成的图​
  • 权：在一个图中，每条边可以标上具有某种含义的数值，此数值称为该边上的权​

    通常权是一个非负实数，权可以表示从一个顶点到另一个顶点的距离、时间或代价等含义。

  • 网：边上标识权的图称为网​

图的基本概念​

完全图​

完全无向图中的每两个顶点之间都存在着一条边；完全有向图中的每两个顶点之间都存在着方向相反的两条边。

假设图中有 n 个顶点，e 条边，则：

完全无向图含有 e=n(n-1)/2 条边​
完全有向图含有 e=n(n-1) 条弧​

稀疏图和稠密图​

这两种图是相对存在的，即如果图中具有很少的边（或弧），此图就称为"稀疏图"；反之，则称此图为"稠密图"。

判断条件：e<nlogn（e：图中边或弧的数量，n：图中顶点的数量） 如果式子成立，则为稀疏图；反之为稠密图。

子图​

设有两个图G＝(V,E) 和 G'＝(V',E') ，若V'是V的子集，即V'⊆V，并且E'是E的子集，即E'⊆E，则G'为G的子图，记为G'⊆G。

生成子图​

若G'为G的子图，并且V'＝V，则称G'为G的生成子图，即包含原图中所有顶点的子图。

临接点​

  • 无向图的邻界点：在一个无向图中，若存在一条边(u,v)，则称顶点 u 与 v 互为邻接点。边(u,v)是顶点 u 和 v 关联的边，顶点 u 和 v 是边(u,v)关联的顶点​

    以顶点 1 为端点的 3 条边是(0,1), (1,2), (1,4)，顶点 1 的 3 个邻接点分别为 0, 2, 4

  • 有向图的邻界点：在一个有向图中，若存在一条弧<u,v>，则称顶点 u 邻接到 v，顶点 v 邻接自 u，弧<u,v>和顶点 u、v 关联​

    顶点 v0 有 2 条出边<v0, v1>，<v0, v2>，1 条入边<v3, v0>，顶点 v0 邻接到 v1 和 v2 ，顶点 v0 邻接自 v3

顶点的度​

顶点的度是图中与该顶点相关联边的数目，记为D(v)。 若一个图有n个顶点和e条边，则该图所有顶点的度之和与边数满足如下关系:

  • 无向图顶点的度：定义为以该顶点为一个端点的边的数目，即该顶点的边的数目，记为 D(v)​

    无向图 G1 ➤ e = (1+3+2+2+2)/2 = 10/2 = 5

  • 有向图顶点的度​

    • 顶点 v 的入边数目是该顶点的入度，记为 ID(v)

    • 顶点 v 的出边数目是该顶点的出度，记为 OD(v)

    • 顶点 v 的度等于它的入度和出度之和，即 D(v)=ID(v)+OD(v)

    有向图 G2 ➤ e = (3+1+2+3+1)/2 = 10/2 = 5

路径和回路​

  • 路径：在一个图中，路径是从顶点 u 到顶点 v 所经过的顶点序列，即(u = vi0, vi1, .., vim=v)。路径长度是指该路径上边的数目​
  • 回路：第一个顶点和最后一个顶点相同的路径称为回路或环​
  • 初等路径：序列中顶点不重复出现的路径称为初等路径​
  • 初等回路：除了第一个顶点和最后一个顶点之外，其余顶点不重复出现的回路​

网中的路径长度​

在网中，从始点到终点的路径上各边的权值之和，称为路径长度。

连通图和连通分量​

  • 连通图：若无向图 G 中任意两个顶点之间都有路径相通，则称此图为连通图​
  • 连通分量：若无向图为非连通图，则图中各个极大连通子图称作此图的连通分量​

强连通图和强连通分量​

  • 强连通图：若有向图中任意两个顶点之间都存在一条有向路径，则称此有向图为强连通图​
  • 强连通分量：若有向图为非连通图，其各个极大强连通子图称作它的强连通分量​

图的遍历​

从图中的某个顶点出发，对图中的所有顶点访问且仅访问一次的过程。

广度优先搜索​

广度优先搜索类似于树的层次遍历。从图中的某一顶点出发，遍历每一个顶点时，依次遍历其所有的邻接点，然后再从这些邻接点出发，同样依次访问它们的邻接点。按照此过程，直到图中所有被访问过的顶点的邻接点都被访问到。

最后还需要做的操作就是查看图中是否存在尚未被访问的顶点，若有，则以该顶点为起始点，重复上述遍历的过程。

深度优先搜索​

深度优先搜索的过程类似于树的先序遍历，所谓深度优先搜索，是从图中的一个顶点出发，每次遍历当前访问顶点的临界点，一直到访问的顶点没有未被访问过的临界点为止。然后采用依次回退的方式，查看来的路上每一个顶点是否有其它未被访问的临界点。访问完成后，判断图中的顶点是否已经全部遍历完成，如果没有，以未访问的顶点为起始点，重复上述过程。——深度优先搜索是一个不断回溯的过程。以上图为例：

  1. 首先任意找一个未被遍历过的顶点，例如从 V1 开始，由于 V1 率先访问过了，所以，需要标记 V-1 的状态为访问过
  2. 然后遍历 V1 的邻接点，例如访问 V2 ，并做标记，然后访问 V2 的邻接点，例如 V4 （做标记），然后 V8 ，然后 V5
  3. 当继续遍历 V5 的邻接点时，根据之前做的标记显示，所有邻接点都被访问过了。此时，从 V5 回退到 V8 ，看 V8 是否有未被访问过的邻接点，如果没有，继续回退到 V4 ， V2 ， V1
  4. 通过查看 V1 ，找到一个未被访问过的顶点 V3 ，继续遍历，然后访问 V3 邻接点 V6 ，然后 V7
  5. 由于 V7 没有未被访问的邻接点，所有回退到 V6 ，继续回退至 V3 ，最后到达 V1 ，发现没有未被访问的
  6. 最后一步需要判断是否所有顶点都被访问，如果还有没被访问的，以未被访问的顶点为第一个顶点，继续依照上边的方式进行遍历

最小生成树​

在一个网的所有生成树中，权值总和最小的生成树称为最小代价生成树（Minimum Cost Spanning Tree)。

构造最小生成树的准则：

  • 只能使用该图中的边构造最小生成树
  • 当且仅当使用 n-1 条边来连接图中的n个顶点
  • 不能使用产生回路的边

图的最小生成树的典型算法​

  • 克鲁斯卡尔（Kruskal）算法

    先构造一个只含 n 个顶点的子图 SG，然后从权值最小的边开始，若它的添加不使 SG 中产生回路，则在 SG 上加上这条边，如此重复，直至加上 n-1 条边为止。

  • 普里姆（Prim）算法

    取图中任意一个顶点 v 作为生成树的根，之后往生成树上添加新的顶点 w。在添加的顶点 w 和已经在生成树上的顶点 v 之间必定存在一条边，并且该边的权值在所有连通顶点 v 和 w 之间的边中取值最小。之后继续往生成树上添加顶点，直至生成树上含有 n-1 个顶点为止。
